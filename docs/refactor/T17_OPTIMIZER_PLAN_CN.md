# T17 新优化器：决定、计划与基准设计

状态：执行中（2026-09-28 起）。用户已逐项拍板并确认汇总，授权执行到第 1 步结束。

## 1. 用户定下的原则

1. 适合大部分电路，不针对某一个电路做针对性优化。面向开源。
2. 分阶段：常温单条件原理图级 → 多 corner → EM。
3. 通用架构开发期间只用 ngspice 和 AnalogGym 的电路；成熟后回到用户自己的电路；之后用户再搭其他类型电路的测试平台做进一步验证。
4. 大语言模型只在 ic-opt 外面：ic-opt 不调用任何模型的接口。

## 4. 基准的设计

代码在仓库的 `benchmarks/`。AnalogGym 的文件不进仓库，由 `benchmarks/fetch_analoggym.py` 按固定版本下载到 `benchmarks/.data/`（不入库）。

### 4.1 被比较的是什么

每个方法都通过产品自己的入口 `ic_opt.blocks.optimize.suggest` 提点，结果用产品自己的 `ic_opt.sim.corner.aggregate` 汇成观测。基准里不另写一套提点或打分的逻辑。

### 4.2 问题

| 层 | 问题 | 用途 |
| --- | --- | --- |
| 合成函数 | 带约束的标准测试函数，放在与真实问题同样的网格上；含一个组合数只有几百的小问题、一个大部分空间不可行的问题、一个部分区域算不出数的问题、一个目标由多个量按公式合成的问题 | 查算法错误；几秒跑完 |
| AnalogGym，场景二 | 每个电路的全部变量，范围取 AnalogGym 自己示例里的范围 | 宽范围起步 |
| AnalogGym，场景一 | 每个电路选一部分变量，范围取参考设计上下各约 30%，档数少；其余变量固定在参考设计 | 围绕已有设计微调 |

每个 AnalogGym 电路的指标由它的两个测试平台（交流直流、瞬态）给出，是"多测试平台、单条件"。

### 4.3 约束与目标怎么定

- 目标：AnalogGym 自己定义的品质因数（放大器用增益带宽积 × 负载电容 ÷ 功耗）。
- 约束的门槛由一套固定的办法算出，不手调：先对每个电路做一次与方法无关的大样本空间填充，再按各指标的分布取门槛，使全部满足的点占比落在预定的档位上。办法在开发用电路上定下来，对留出的电路原样套用。
- 参考设计：大样本里满足全部约束且目标最好的点（没有可行点时取违反最少的点）。

这套办法在看任何数据之前写定（2026-09-28），由 `benchmarks/icopt_bench/calibrate.py` 执行，每个电路同样处理：

| 步 | 做法 |
| --- | --- |
| 大样本 | 每个电路 2048 个点：1024 个在各变量的线性坐标上均匀（Sobol 序列），1024 个在对数坐标上均匀；都落到网格上。种子由电路名算出 |
| 可用的点 | 全部指标都算出数的点 |
| 被约束的指标 | AnalogGym 自己给这个电路列出目标的那些指标，方向照它的 |
| 门槛 | 所有指标取同一个分位水平 q：要求"不小于"的指标，门槛取它在可用的点上的 q 分位数；要求"不大于"的取 1 − q 分位数。q 在 0.001 的刻度上取"全部满足的点占全部 2048 个点的比例不低于 0.5%"的最大值。门槛保留三位有效数字，向放宽的方向取整 |
| 排除 | 可用的点不足 40 个（2%），或者找不到满足比例的 q 的电路，不进基准，原因记在电路表里 |
| 参考设计 | 大样本里全部满足的点当中目标最好的一个 |
| 场景二的问题 | 全部变量、电路表里的范围、上面的门槛；没有起点 |
| 场景一的变量 | 影响最大的 6 个：一个变量的影响 = 它与各被约束指标及目标值的秩相关系数绝对值的最大值（在可用的点上算）；并列时按名字 |
| 场景一的范围 | 以参考设计为中心：步长取参考值的 10%（取到原网格步长的整数倍，至少一个原步长），上下各取不超过 30% 的档数（至少一档、至多三档），超出电路表范围的档去掉；其余变量固定在参考设计 |
| 场景一的问题 | 门槛与场景二相同；起点是参考设计 |

0.5% 的含义：随机取点时，200 个点里碰到可行点的概率约 63%，50 个点里约 22%。三档预算下随机取点的成功率都不贴近 0 或 1，方法之间的差别能看出来。

### 4.4 度量

| 度量 | 定义 |
| --- | --- |
| 找到可行点所需的点数 | 第一个满足全部约束的点的序号；预算内没找到记为"未找到" |
| 固定预算下的目标值 | 前 50、100、200 个点里可行点的最好目标值 |
| 成功率 | 预算内找到可行点的运行占比 |

每个（问题、方法）报告各种子的中位数和最差的四分之一。一次 200 点的运行同时给出 50、100 点处的读数，所以各方法的初始设计点数在基准里固定给定，不随预算变。

### 4.5 留出

划分在看任何结果之前用固定的随机种子定下，按电路类别和变量个数分层，写进 `benchmarks/split.json`。留出电路的结果只在每个阶段结束时计算；每次查看都在 `benchmarks/HELDOUT_LOG.md` 里记一行（日期、原因、看了什么）。

### 4.6 计算资源

基准运行按 32 线程并行：每个进程单线程，数值库的线程数设为 1。仿真结果按（电路、参数）落盘缓存，相同的点不重复仿真。

## 5. 数值核心的骨架（D14）

| # | 做法 |
| --- | --- |
| 1 | 每个指标各建一个模型，不给目标值单独建模。目标值和约束余量用 spec 里的公式从各指标的预测值算出 |
| 2 | 指标算不出数的点单独处理：另建一个"这里能不能算出数"的模型，不写罚分 |
| 3 | 分两段：还没有可行点时，目标是"离全部满足还差多少"；有了可行点之后，在大概率可行的前提下提高目标值 |
| 4 | 第一批：当前设计、已知好点、其余用空间填充 |
| 5 | 以当前最好的点为中心划一个范围，连续变好就放大，连续没进展就缩小；每批留一部分点在整个空间里找。比例按空间大小定。范围缩到最小后保留全部数据，换一个新的中心 |
| 6 | 一批里的点互相错开 |
| 7 | 范围跨度大的变量按对数尺度搜索；点落在 spec 的网格上；不重复已评估的点 |
| 8 | 状态可由记录重建：同样的记录和种子给出同样的点 |

## 6. 已知风险

1. AnalogGym 是开源工艺上的放大器和稳压器，和毫米波电路不同类。
2. 小空间上新核心可能只是"不退步"。
3. 模型和选点都自己写，靠合成函数核对和对照来发现错误。
4. 代理建议的实际价值要到第 1.5 步才能量出来。

### 第 0b 步（T17.0b，2026-09-28）：修现有策略的喂数、初始设计归我们、第一批含当前设计

改了什么：

- 喂数：OpenBox 收到每个点的真实目标值（约束不过的点用 `fom` 按方向取号），指标失败 / 仿真失败的点作为 OpenBox 自己的 FAILED 试验（它用成功试验各列的最大值填补）；spec 无目标时每个非失败点喂 0.0。还没有可行点时，EIC 的参考值取成功试验里最大的目标值（在我们的包装里替换该 `History` 实例的 `get_incumbent_value`，按 OpenBox 0.9.0 核对，有测试守住）。TuRBO 每次从全部历史按同一尺度造目标：有可行点时不可行点排在最差可行点之上 1–4 个跨度（按 `sqrt(constraint_penalty)`，截在 3），失败点取其余点的最大值；没有可行点时目标就是违反量。信任域回放按本次调用的尺度判断"这批是否变好"。`failure_penalty` 保留为关键字但不再起作用；`penalized_objective` 标为弃用。
- 初始设计：OpenBox 策略的初始设计由 ic-opt 抽（每个 spec 与种子一份 Sobol，取 2 的幂再截前 n 个，不再告警，前缀稳定），与批大小无关按序发出；跨过设计末尾的那一批，其余点在历史里已有"变量数 + 1"（至少 2）个成功点时交给代理模型，否则继续空间填充。每个点的 origin 写 `:init` / `:acq`；plan 行按此规则逐批算出代理模型提出的点数。`opt.optimize` 现在每批都传运行种子本身（各策略自己按历史长度偏移）。
- 起点：`suggest(start=...)` 先发还没评估过的起点（origin `start`），算作初始设计；`opt.optimize` 先放导出网表里的当前设计（各测试平台须一致；格点之间移到最近格点并说明；越界、不是数、带器件的 spec 都给一行原因），再放 `start=文件` 的点。`optimize`、`coarse_to_fine`（粗搜一步）、`signoff`（搜索一步）都有 `current=` / `start=`。续跑不重复。TuRBO 现在也把无标签行（起点、热启动行）算进它的初始设计。
